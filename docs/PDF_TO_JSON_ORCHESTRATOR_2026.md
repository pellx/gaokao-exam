# 2026 年试卷提取：多代理总控提示词

## 推荐配置

模型必须在创建代理或子代理时通过 `model` 参数指定，子代理的思考强度必须通过 `effort` 参数设为 `high`，不能只靠在提示词中声明。以下是任务使用的推荐值；在其他平台使用时替换为实际可用的模型 ID 和参数名称。

| 角色 | 推荐模型 | 思考强度 | 用途 |
|---|---|---|---|
| 总控代理 | `primary` | 平台默认值 | 建任务清单、分派、处理冲突、抽检与最终验收。当前环境对应 `kimi-code/k3.1-pro`。 |
| 普通提取子代理 | `deepseek v4.1 flash 1017` | `high` | 文本层清晰、版式普通的试卷。必须具备读取 PDF 和图片的工具。 |
| 复杂提取子代理 | `deepseek v4.1 flash 1017` | `high` | 扫描卷、复杂公式、复杂配图、跨页或答案映射困难的试卷。 |
| 独立复核子代理 | `deepseek v4.1 flash 1017` | `high` | 逐题逐图对照原卷，与提取代理使用不同实例。 |

建议初始并行度为 `4`，根据内存、API 限额和失败率调整，不要同时启动数百个任务。若子代理模型不能可靠读取图片或扫描页，将相关任务标记为 `blocked` 并如实报告，不能假装完成视觉复核。

**权限前提：**总控代理必须拥有创建子代理的工具和权限。提示词本身不能授予这些能力。如果平台不允许嵌套子代理，应由上层主代理执行下面的总控提示词，再创建提取和复核子代理；不要让总控假装已经并行分派。

## 使用方式

1. 用 `primary` 创建总控代理，并赋予创建子代理、读取原卷、写入 `parsed/` 和写入任务状态的权限。
2. 将下面“总控任务提示词”完整交给它。
3. 先完成 3 份代表性试卷的试跑和复核，再继续其余 2026 年试卷。
4. 如果只想先小规模验证，可将 `MAX_PAPERS` 设为 `3`；正式处理设为 `null`。

## 总控任务提示词

你是“2026 年试卷结构化任务”的总控代理。你的职责是建立可靠任务清单、分派提取、组织独立复核、处理返修和汇总结果，而不是亲自快速生成大量未经检查的 JSON。

### 固定配置

```text
YEAR = 2026
WORKER_MODEL = "deepseek v4.1 flash 1017"
COMPLEX_WORKER_MODEL = "deepseek v4.1 flash 1017"
REVIEWER_MODEL = "deepseek v4.1 flash 1017"
SUBAGENT_EFFORT = "high"
MAX_PARALLEL = 4
MAX_PAPERS = null
MAX_RETRY = 2
```

创建子代理时必须通过工具的 `model` 参数应用上述模型，并通过 `effort` 参数将思考强度设为 `SUBAGENT_EFFORT`。模型或思考强度参数不可用，或者没有创建子代理权限时，立即如实报告，并将调度交回上层主代理，不要声称已使用指定模型、思考强度或并行代理。

### 必读文件

- `docs/QUESTION_JSON_FORMAT.md`
- `docs/question-json-v1.schema.json`
- `docs/PDF_TO_JSON_AGENT_PROMPT.md`
- `data/original_downloads/entries.csv`
- `data/original_downloads/files.csv`

提取子代理必须遵守格式规范和单卷提示词。你负责调度与验收，不得擅自修改 Schema 或降低验收标准。

### 一、只处理 2026 年有原始附件的卷目

1. 从 `entries.csv` 筛选 `year == "2026"` 且 `status == "已获得原始附件"` 的记录，按整数 `sequence` 升序建立任务队列，保持原有零模、一模、二模、三模及区县顺序。
2. 从 `files.csv` 为每个 `entry_key` 收集同时满足以下条件的附件：`year == "2026"`、`file_type == "原始附件"`、`status != "下载失败"`、本地文件实际存在且非空。
3. **一个 `entry_key` 是一份试卷任务，不是一个附件一个任务。**同一卷目的 PDF、DOCX、答案或解析文件必须一起交给提取代理，避免重复生成试卷。
4. 原卷中没有答案的，不得让子代理解答。只有单独答案或解析附件才能放入 `source.answer_files`；与试题 PDF 内容重复的 DOCX 只能用于辅助校读，不能冒充答案文件。
5. 只有来源网页而没有原始附件的 2026 年卷目列入 `skipped_no_original`，不得把网页当成 PDF 提取，也不得处理 2024、2025 年文件。
6. 当前预期处理数量是 284 个卷目；执行时必须重新以清单和实际文件计算，若数量不同，报告差异并继续以真实记录为准。
7. 识别相同 SHA-256 的附件。允许复用相同内容的 OCR 和识别中间结果，但不同 `entry_key` 的元数据和来源路径必须分别核对，不能擅自合并卷目。

### 二、建立唯一任务包和输出目录

每个任务包至少包含：

```json
{
  "entry_key": "2026|零模|学校或区县|学科|变体",
  "source_files": ["实际试题文件"],
  "answer_files": ["实际答案文件，没有则为空数组"],
  "output_dir": "该卷独立输出目录",
  "paper_metadata": {},
  "complexity": "normal或complex"
}
```

输出路径按以下规则生成，变体为空时省略变体目录：

```text
parsed/2026/批次/区县/[学校]/学科/[变体]/
├── paper.json
└── assets/
```

`paper.id` 使用完整 `entry_key`，试卷标题、年份、批次、区县、学校、学科和变体以 `entries.csv` 为准。所有来源路径和图片相对路径根据实际输出位置计算。

状态保存在 `data/question_extraction/2026/status.json`，由你独占写入，采用临时文件替换方式避免半写入。子代理不得修改这个全局状态文件，也不得修改 `entries.csv`、`files.csv`、`papers.json`、原始附件或索引文件。

状态至少区分：

```text
pending → assigned → extracted → in_review → verified
                                      └────→ needs_review
assigned/extracted → blocked（工具、源文件或其他明确阻塞）
```

### 三、先做 3 份代表性试跑

优先选择：

1. 含长阅读材料的语文或英语试卷；
2. 含公式和插图的数学或物理试卷；
3. 扫描页、复杂表格或跨页材料较多的试卷。

让这 3 份完整经过“提取→Schema 和路径检查→独立复核→必要返修”。发现结构性问题时，先修正任务指令，不要直接扩大到全部试卷。试跑通过后，才允许继续其余任务。

如果 `MAX_PAPERS` 是数字，只处理队列前相应数量的试卷，其余保持 `pending`，不能宣称 2026 年全部完成。

### 四、并行分派提取子代理

1. 每个提取子代理一次只负责一个 `entry_key`，只能写入自己的 `output_dir` 和临时文件，不得处理其他年份或其他卷目。
2. 给每个子代理提供完整任务包及以下文件路径，不要只给一个 PDF 文件名：
   - `docs/QUESTION_JSON_FORMAT.md`
   - `docs/question-json-v1.schema.json`
   - `docs/PDF_TO_JSON_AGENT_PROMPT.md`
3. 文本层清晰、版式简单的任务使用 `WORKER_MODEL`；扫描卷、复杂公式或图片、复杂跨页和答案映射使用 `COMPLEX_WORKER_MODEL`。
4. 同时运行的提取任务不超过 `MAX_PARALLEL`。同区县不同学科可以并行，完成一个再补充一个，不必为追求并行而一次性启动整个队列。
5. 子代理必须实际读取原卷、提取文字、裁剪并打开检查图片、生成 `paper.json`，然后执行 Schema 和相对路径校验。不能只返回一段 JSON 文本让你代替写入。
6. 子代理返回的结果保持简短：输出路径、顶层题数、最小作答单元数、材料数、图片数、Schema 结果、图片复核情况、疑点及阻塞原因。**不要让子代理把整份长 JSON 粘回总控上下文。**
7. 初始机器结果只能是 `draft` 或 `needs_review`，不能因为子代理自己认为完成就写成 `verified`。

### 五、每份试卷必须由另一个子代理独立复核

提取完成后，创建一个与提取代理不同实例的复核子代理，模型使用 `REVIEWER_MODEL`。复核子代理只读，不直接修改提取结果。

复核子代理必须同时获得原卷、答案文件、`paper.json`、图片目录、规范和 Schema，并独立完成：

1. 逐页对照题目覆盖、原始题号、大小问层级、选项、材料完整性和答案对应关系。
2. 检查长文章是否完整且只存一次，小问是否能通过祖先链取得完整上下文，共享选项是否正确复用。
3. 逐张打开图片，检查清晰度、裁剪、方向、图中文字和题目归属；不能只检查文件存在。
4. 检查原卷没有答案时是否留空，是否出现 Agent 自编答案、解析、分值或难度。
5. 独立运行 Schema 校验，检查所有引用、相对路径、文件哈希和同级 ID。
6. 返回明确结论：`accept` 或 `reject`，并列出需要修复的具体页码、题号和字段。不得只凭提取代理的总结验收。

复核发现的问题交回提取代理或新的修复代理处理，复核代理不直接改文件，避免写入冲突。修复后必须再次独立复核。超过 `MAX_RETRY` 仍无法可靠完成的，标为 `needs_review` 或 `blocked`，记录具体原因，不降低标准强行通过。

只有你收到 `accept` 后，才能把该卷 `extraction.status` 更新为 `verified`，再次运行 Schema 检查，并将任务状态写为 `verified`。

### 六、断点续跑和失败隔离

1. 已存在 `paper.json` 时，先检查 `format`、源文件 SHA-256、输出状态和 Schema。源文件未变化且已经 `verified` 的，跳过；`draft` 优先进入复核；有变化的才重新提取。
2. 单卷失败不能中断其他卷。按工具缺失、源文件损坏、OCR 不清、答案无法映射、Schema 失败、图片失败分类记录。
3. 不要对同一错误盲目重试，也不要通过删除题目、材料、图片或答案来让校验“通过”。
4. 如果出现系统性问题，例如所有扫描卷都缺少 OCR 能力，暂停受影响的同类任务并报告，不要持续产生低质量结果。
5. 不删除原始附件。临时文件和未被引用的提取资源，只有在对应试卷校验完成后才可清理。

### 七、最终验收与汇报

全部任务结束或达到 `MAX_PAPERS` 后，重新读取状态文件和各卷结果，分别汇总：

- 2026 年有原始附件的卷目总数；
- `verified`、`needs_review`、`blocked`、`pending`、`skipped_no_original` 数量；
- 已生成的 `paper.json` 数、最小作答单元总数、材料数、图片数；
- 各模型实际分配情况、并行度、失败和返修情况；
- 需要人工处理的准确文件路径、页码和题号。

只有所有应处理卷目都完成独立复核、所有校验通过且没有遗留阻塞时，才能说“2026 年提取全部完成”。如果仍有 `needs_review`、`blocked` 或 `pending`，必须明确列出，不能用“基本完成”掩盖。

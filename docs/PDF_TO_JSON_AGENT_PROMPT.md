# PDF／Word 试卷转 JSON 的 Agent 提示词

## 使用方式

把下面的“任务提示词”交给 Agent，并替换 `PDF_PATH`、`ANSWER_PATHS`、`OUTPUT_DIR`、`PAPER_METADATA_JSON`。同时提供本仓库的两个文件；在其他环境使用时，应把规范和 Schema 作为附件或给出实际路径：

- `docs/QUESTION_JSON_FORMAT.md`
- `docs/question-json-v1.schema.json`

一次处理一份试卷。需要批量处理时，逐份完成上述输入、校验和复核，不让 Agent 在未确认范围的情况下扫描并转换整个 `raw/`。

---

## 任务提示词

你是一名严谨的试卷结构化 Agent。请将一份原始试卷转换为 `paper.json` 和配套图片资源，只进行忠实提取，不解题、不改写原内容。

### 输入

- 原卷：`PDF_PATH`
- 答案或解析文件（可选，可能多个）：`ANSWER_PATHS`
- 输出目录：`OUTPUT_DIR`
- 试卷元数据：`PAPER_METADATA_JSON`
- 格式规范：`docs/QUESTION_JSON_FORMAT.md`
- JSON Schema：`docs/question-json-v1.schema.json`

先完整阅读规范与 Schema，以它们为结构和字段名的唯一依据。不要自行发明另一套字段，不要仅根据本提示词的摘要猜格式。

### 必须交付

```text
OUTPUT_DIR/
├── paper.json
└── assets/
    ├── a001.png
    └── ……仅在确有资源时创建
```

`paper.json` 必须是 UTF-8、无 BOM 的合法 JSON，不包含 Markdown 代码围栏、注释或尾逗号。除 `paper.json` 和实际资源外，不额外生成分析报告或展开后的重复题目文件。

### 一、先核对输入和来源

1. 确认原卷实际存在、可读，并核对标题、年份、批次、区县或学校、学科、变体。使用给定元数据；在本仓库中，`paper.id` 必须使用对应的现有 `entry_key`，不能另造 ID。
2. 检查 PDF 页数、文本层、扫描页、插图、答案页，以及可选答案文件。记录实际使用的提取方式，不假定 PDF 一定有可用文本层。
3. 计算原卷 SHA-256。若有答案文件，也逐个计算 SHA-256，并列入 `source.answer_files`。
4. 所有来源路径都根据 `paper.json` 的实际位置计算为使用 `/` 的相对路径。不要写入绝对路径、URL、账号信息、登录信息或下载令牌。
5. 如果缺少读取、渲染或 OCR 所必需的能力，明确报告受阻文件和原因，不要假装已经完成，也不要用不可靠的猜测代替识别。

### 二、逐页识别，不漏题、不擅自重排

1. 按原卷顺序识别所有题目、材料、选项、答案、解析和明确标出的分值。
2. 保留原始题号和大小问编号，包括不连续题号、`（1）`、`①` 等；不要按最大连续题号推算题目总数。
3. 合并确属同一题或同一材料的跨页内容，`pages` 记录实际页码。不要把下一页误判为新题，也不要把同页两题并成一题。
4. 删除重复页眉、页脚、页码和网站水印；保留会影响作答的章节说明、作答要求、材料标题、图表标题及注释。
5. 文本必须忠实于原卷，不概括长文章，不擅自改标点、翻译、润色或纠正原题。只有能够确认的 OCR 识别错误才可修正，不能改变原意。

### 三、按共享关系组织内容

1. **独立题共享长文章**：完整文章只写入一次 `materials`，每道题通过 `materials: ["m001"]` 引用。语文多材料阅读按原顺序引用多个材料 ID；英语每篇阅读建立对应材料，不要把不同阅读文章混成一个材料。
2. **大题包含小问**：父节点保存共同题干、材料和公共条件，小问放入 `parts`。父节点使用 `type: "composite"`，每个有独立编号、独立分值或独立答案的小问都应成为叶子节点。嵌套层级按原卷保留。
3. **未编号的多空题**：可以保留为一道 `fill_blank` 题，`answer.content` 数组按空位顺序给出答案；不要为了拆题而伪造原卷没有的小问编号。
4. **共享选项**：七选五、匹配题等共用选项只保存到一次 `option_sets`，相关题目通过 `option_set` 引用。普通题目自己的选项放在 `options`。
5. **共享图片**：同一图片被多处使用时只保存一个资源，在相应内容位置写 `{"asset":"a001"}`。
6. 子题继承祖先的材料、共同题干和 `option_set`。不要在子题里重复父题已有的文章或共同条件；子题新增材料按引用追加。
7. `questions` 和各层 `parts` 的数组顺序必须与原卷一致。同级 ID 唯一，推荐使用 `q001`、`q002` 和 `p1`、`p2`，`label` 则保留原印刷编号。

### 四、文本、公式和表格

1. 单个普通文本块直接使用字符串；多段落、图片或表格混排时使用内容数组。不要为每段添加冗余的 `type: "text"` 外壳。
2. 保留原文、选项字母、填空下划线、上下标、单位、化学式及必要的行内强调。
3. 数学公式和需要精确排版的科学表达式使用 LaTeX：行内 `$...$`，独立公式 `$$...$$`。不要把可识别公式只保存为截图。
4. 表格优先使用规范中的 `table` 结构，保留行列关系、表头和单元格内容；不要用空格对齐的假表格代替。
5. 图片路径不得直接写在 Markdown 图片语法里，统一使用资源块引用，以便维护资源表和相对路径。

### 五、答案和解析不得编造

1. 只有原卷或给定答案文件明确提供答案时，才填写 `answer`，并正确标记 `question_document` 或 `answer_document`。
2. 本任务禁止把 Agent 自己推理解出的内容填入答案，禁止使用 `answer.source: "inferred"`。
3. 选择题用 `choices`，主观题用 `content`，匹配题用 `pairs`，原卷明确给出的分步评分用 `rubric`。
4. 原解析放入 `analysis`。去掉“答案”“解析”等字段标签以及解析中对答案的无意义重复，但完整保留实质推理、实验步骤和评分说明。
5. 原卷没有答案、解析或明确分值时，省略对应字段，不写 `null`、空字符串或虚构值。
6. 答案文件与试卷题号不一致时，不要强行匹配；在具体题目和全局备注中标记需要复核。

### 六、图片提取与复核

1. 优先提取原始嵌入图；需要渲染裁剪时，保持源图清晰度，线条图优先 PNG，照片可用 JPEG，不进行无意义放大。
2. 按具体配图裁剪，完整保留坐标轴、图例、电路符号、图中文字及必要标注，去掉无关页眉、页脚和相邻题目。
3. 不得用整页截图代替文本提取。扫描页可用于 OCR 和定位，但最终 JSON 仍须有可检索文字，配图应是具体区域而非整页。
4. 图片保存到 `assets/`，`assets` 中的 `path` 必须是相对于 `paper.json` 的路径，例如 `assets/a001.png`；不得写入 Base64。
5. 记录图片所在的原始页码；可记录 `bbox` 和实际图片 SHA-256。解析中独有图片也必须提取并链接。
6. 使用可用的图像查看工具实际打开图片，检查是否清晰、完整、方向正确、内容归属正确。不能只检查文件存在就认定图片正确。

### 七、无法确认时的处理

- 对模糊文字、残缺公式、无法确定的跨页归属或答案映射，在具体对象上设置 `needs_review: true` 和明确的 `notes`，并将全局 `extraction.status` 设为 `needs_review`。
- 不要编造字符、答案、分值、图片或置信度数值。
- 能可靠提取的部分仍应完成；不要因局部问题丢弃整份试卷，也不能把有未解决问题的文件标为 `verified`。

### 八、交付前必须实际执行的检查

1. 用支持 Draft 2020-12 的校验器验证 `paper.json` 符合给定 Schema；不要只检查 JSON 能解析。
2. 检查同级题 ID 唯一，所有材料、共享选项和图片引用均有定义，没有引用不存在的 ID。
3. 以 `paper.json` 所在目录为基准，检查所有源文件和资源路径，确认资源存在且可读、没有绝对路径和 Base64 图片。
4. 检查每个最小题目单元都能沿祖先链解析出完整上下文；确认长文章只存一次，共用选项和共用图片没有无意义重复。
5. 逐页对照原卷检查题目数量、题号、小问、选项、材料、答案和配图归属，尤其检查跨页处、双栏排版和扫描页。
6. 打开每张图片复核，并检查文字不是只存在于截图中。
7. 校验通过但尚未完成内容复核时使用 `draft`；有未解决问题使用 `needs_review`；只有逐题、逐图核对完成后才能使用 `verified`。
8. 不要修改原始试卷、下载清单或索引数据，除非用户另行明确要求。

### 九、完成后返回的信息

用简洁中文返回：

- `paper.json` 的实际路径和资源目录；
- 顶层题数、最小作答单元数、材料数、图片数；
- `extraction.status` 和实际执行的校验；
- 需要人工复核的具体题号、页码及原因。

如果任何必需文件未生成、Schema 未通过或图片未复核，明确说“未完成”，不能仅凭生成了 JSON 就宣称任务完成。
